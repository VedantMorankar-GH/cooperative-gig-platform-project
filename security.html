SECURITY & PRIVACY AUDIT

Prototype security with least privilege.

Co-opGig demonstrates prototype-level identity, role-based authorization, resource ownership, data minimization and auditability. LocalStorage is demo persistence, not production-secure authentication.

🔐 Authentication

Demo sessions use centralized current-user state. No passwords, access tokens or secret keys are stored by the application.

🛡 RBAC

Exactly four roles are supported: Customer, Worker, Cooperative Federation Administration and Platform Admin. URL role parameters cannot grant permissions.

🔎 Resource ownership

Bookings, conversations, reviews, verification and complaint actions are checked against the authenticated demo identity and federation scope.

📍 Privacy

Operational screens use service areas and approximate locations. Private home coordinates and unnecessary sensitive information are not exposed.

🧾 Audit trail

Important administrative actions, federation actions and demo session events are retained in the centralized audit log.

🧼 Safe rendering

User-generated reviews, messages, complaints and other untrusted text are rendered through escaped output where dynamic HTML is used.

⚠ Prototype boundary: LocalStorage can be inspected or modified by a user running the frontend. Therefore prototype RBAC is a demonstration of application architecture, not a substitute for backend-enforced authorization.

Production security roadmap

For production, replace demo identity/state controls with:

Frontend → HTTPS → Backend API → Authentication / Server-side RBAC → Database → Encrypted Storage

Required controls include secure cookies or equivalent sessions, password hashing, MFA where appropriate, backend validation, database authorization, encryption at rest/in transit, rate limiting, secrets management, backups and monitoring.
